---
title: Query Parameters
description: Type-safe URL query parameter parsing in ion_extra
---

`req.query()` decodes URL query parameters into typed DTOs using the same `JsonObject` API as `req.json()`, including validation rules.

## Basic Usage

Define a filter DTO with `JsonObject`:

```dart
import 'package:ion_extra/ion_extra.dart';

class UserFilters {
  UserFilters.fromJson(JsonObject json)
      : page   = json.int('page', rules: [.range(min: 1)]),
        limit  = json.intOrNull('limit') ?? 20,
        search = json.stringOrNull('search'),
        tags   = json.listOrNull('tags', .string) ?? const [];

  final int page;
  final int limit;
  final String? search;
  final List<String> tags;
}
```

Parse in a handler:

```dart
// GET /users?page=2&search=alice&tags=dart&tags=flutter
app.get('/users', (req) {
  final filters = req.query(UserFilters.fromJson);
  return JsonList(findUsers(filters));
});
```

If validation fails, `req.query()` throws `ValidationErrors` just like `req.json()`, with all errors collected. Pass `failFast: true` to throw on the first error instead.

## Type Conversion

Query values stay strings until a getter reads them, and each getter converts the string to the type it asks for. `?zip=007` reads as `'007'` with `json.string('zip')`, and `?page=2` as `2` with `json.int('page')`.

| Getter | Accepts | Rejects |
| --- | --- | --- |
| `int` | `42`, `-5` | `+5`, `0x1F`, `1e3` |
| `double`, `num` | `3.14`, `-12.50`, `1.5e2` | `NaN`, `Infinity` |
| `bool` | `true`, `false` | `1`, `True`, `yes` |
| `string` | anything | |

An empty value such as `?topic_id=` counts as absent for every type except `string`, so `json.intOrNull('topic_id')` returns `null`.

## Lists

A single value is accepted where a list is expected, so `?ids=5` reads as `[5]` with `json.list('ids', .int)`. All notations are supported and can be mixed:

```
?tags=dart&tags=flutter           # repeated keys
?tags[]=dart&tags[]=flutter       # bracket notation
?tags[1]=flutter&tags[0]=dart     # indexed notation, ordered by index
?items[0][id]=1&items[1][id]=2    # list of objects
```

Item errors are reported at the item path, such as `ids.1`.

## Nested Objects

Use dot or bracket notation for nested filter objects:

```
?filter.page=1&filter.search=alice
?filter[page]=1&filter[search]=alice
```

Parse with `json.object('filter', NestedDto.fromJson)`. `json.keys` lists the normalized names, so `?filter[page]=1&tags[]=dart` has the keys `filter` and `tags`.
